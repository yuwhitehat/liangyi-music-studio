## 🔐 登录与身份

独立工作室老师人数少，**不做邀请码、不做自助注册老师**。

### 登录方式（二选一）

| 方式 | 说明 |
|---|---|
| **手机号验证** | 输入手机号 → 查 `teachers` 集合 → 命中即为老师，姓名取自登记表 |
| **微信一键登录** | `<button open-type="getPhoneNumber">` → 云函数用 `code` 换真实手机号 → 同上判定 |

### 身份判定规则

```
手机号 ──► teachers 集合里有？
            ├─ 有  → 老师端（姓名来自登记表，无需手填）
            └─ 没有 → 走学员路径，仅这一步补一次姓名

```

- 老师**不需要填任何资料**，登录页只有手机号一个输入框
- 手机号未登记却点了「我是老师」，会提示联系工作室，可一键转学员身份

| 我是学员 | 学员名册前 4 位（首位标「有排课」） | 填入手机号 **+ 姓名**，直接登录，跳过补姓名那一步 |

提示文案也跟着身份变：老师入口写「超管可管理老师与权限」，
学员入口写「学员直接进，无需再填姓名」。

上线前把 `pages/login/login.js` 顶部的 `DEV_MODE` 改成 `false`，
整张卡片自动隐藏（`wx:if="{{devMode}}"`），这是唯一开关。

### 超管添加老师的「口子」

- 云函数 `cloudfunctions/admin`，入口白名单 `SUPER_ADMINS`（**部署后必须填入超管 openid**）

- 动作：`addTeacher` / `listTeachers` / `removeTeacher`（不可移除超管）

  点进 `pages/teacher/teachers/` 独立页面，上半为名单查询（可按姓名/手机号搜），下半为添加表单

### 导航修正（重要 bug）

旧版在**点击入口时就写入 role**，而首页 `onShow` 检测到 role 就自动跳转
→ 从登录页返回首页的瞬间会被弹进老师端。

现已拆成两层：

| 状态 | 含义 | 何时写入 |
|---|---|---|
| `pendingRole` | 只是"点了哪个入口"的意图 | 点击入口时 |
| `role` + `session` | 已确认的登录身份 | **登录成功后** `app.signIn()` |

- 首页 `onShow` 只在 `app.isLoggedIn()` 为真时才跳转
- 首页 → 登录页改用 `navigateTo`，左上角返回 = 真正回上一页
- 登录页去掉「切换身份」，改为「← 回到首页」（`reLaunch` 清栈）
- 登录成功后用 `reLaunch` 进工作台，避免回退到登录页
- 退出登录走 `app.signOut()`，清掉 session，首页才不会自动弹回工作台

### 时间冲突规则

两条独立规则，都在 `utils/lessons.js`：

| 规则 | 判定 | 原因 |
|---|---|---|
| **课程时间** | 同日 + **同课程类型** + 区间交叉 → 冲突 | 不同课程可由不同老师同时开，时间**允许重叠** |
| **学员时间** | 同日 + 同一学员 + 区间交叉 → 冲突 | 一个人同一时刻只能上一节课，**跨课程类型也互斥** |

```js
function overlap(a, b) {
  if (a.courseType !== b.courseType) return false   // 不同类型可并行
  return timeCross(a, b)
}
```

校验覆盖三处：课表已存课、本批次待排、周期展开后的每一节。冲突逐条列出日期与原因，
不冲突的正常排入（部分成功）。

### 固定课（周期性排课）

学员有每周固定时间的课，排一次即可，不用每周重复操作：

- 排课页「**重复**」：不重复 / 每周 / 隔周
- 「**上几节**」：4 / 8 / 12 / 24 节，并实时预览「每周六 15:00 起，共 8 节，到 11月14日」
- 确认时由 `expand()` 展开成 N 节具体日期的课，共享 `seriesId` 便于日后整组管理
- 每节课带节次标记 `1/8`，在老师端今日课表、约课管理、学员课表都会显示
- 固定课添加后**不再自动顺延开始时间**（它已占住整周，顺延没意义）
- 展开时若某一周撞上冲突，只跳过那一周并说明原因，其余照常排入

### 种子数据版本化（重要机制）

`list()` 只在缓存为空时播种 —— 这意味着**后来给 SEED 加的字段永远到不了老设备**。
「课时档案卡只有张小明有」就是这个原因：档案字段是我加完种子之后才补的，
老缓存里其他学员的 `totalLessons` 被 `normalize()` 补成 0，判定为「无档案」就不显示了。

现在 `students` / `teachers` 都带版本号与升级合并：

```js
const SEED_VER = 2                 // 给 SEED 加字段时 +1
function upgrade(rows) {           // 按 id 从 SEED 补缺失字段
  // 只填「缺失 / 0 / 空」的值 —— 老师手动编辑过的数据不会被覆盖
}
```

配合 `normalize()`（读取时补默认值）+ `upgrade()`（一次性补齐并回写），
以后加字段只需把 `SEED_VER` 加一，老用户自动获得新字段，且不会丢自己的改动。

### 课时口径：基线 + 增量

`已上 = doneBefore（基线） + 本小程序内完成的课数`

这样老师录入的历史节数不会丢，之后在小程序里签到的课也会自动累加。
但带来两个必须处理的坑：

**① 表单不能直接编辑基线**

表单让老师填的是「**一共上了几节**」（和列表展示口径一致），
提交时换算成基线存储：

```js
doneBefore = max(0, 老师填的总已上 − 系统内已完成数)
```

否则老师看到列表是 12、去表单里改成 12，保存后又变成 12+4=16 —— 数字会跳。

**② 超支要如实显示，不能 `Math.max(0, …)` 吞掉**

上了比报名还多的课（忘记录入新课时包很常见），旧代码 `remain` 钳在 0，
看起来"刚好上完"，实际已经超支。现在：

| 位置 | 表现 |
|---|---|
| 学员端档案卡 | 剩余格变成「**已超 N 节**」（砖红），进度条变红，下方提示找老师补课时 |
| 老师端学员列表 | 名字下方加「已超 N 节」红色标记 |
| 老师端签到后 | 若这节课让任一学员超出报名数，**当场弹窗提醒**列出是谁、超几节 |

`remain = total - used` 允许为负，`over / overBy` 单独给出，界面据此渲染。

### upgrade() 的两个易错点

给种子加字段时的 `upgrade()`，有两个坑都踩过：

```js
// 坑 1：不能把 0 / '' 当"缺失"
if (!(k in out) || out[k] == null) out[k] = seed[k]   // ✓ 只补真正缺失的
// ✗ 旧写法把 cur === 0 也当缺失 → 新学员 doneBefore=0 被种子的 8 覆盖

// 坑 2：upgrade 必须作用于原始缓存
const rows = normAll(upgrade(saved))    // ✓
// ✗ normAll(upgrade(normAll(saved)))：内层 normalize 先把字段补成 0，
//    upgrade 就再也分不清「老缓存没这字段」和「老师填了 0」，补齐失效
```

`utils/quota.js` 独立成模块，因为 `students` 与 `lessons` 互相有依赖，
汇总逻辑放任意一边都会循环引用。

### 课时档案卡的显示条件

```js
show = 共报 > 0 || 有报名日期 || 已有上课记录
```

| 登记了但没填课时 | 只显示有数据的那几格 |
| 自助注册、已有上课记录 | 只显示「已上 N 节」 |
| 自助注册、完全没记录 | 卡片隐藏（此时确实无可展示） |

### 两个「点了没反应」的坑（已修）

**① `wx.showModal` 的按钮文案最多 4 个字**

超出会**静默失败** —— 弹窗根本不出现，控制台也没有错误，表现就是"点了没反应"。
项目里曾有 3 处违规：`'复制老师电话'`(6)、`'以学员身份进入'`(7)、`'换个手机号'`(5)。

现在统一走 `utils/dialog.js`：

```js
const dialog = require('../../../utils/dialog.js')
dialog.show({ title, content, confirmText: '复制老师电话' })
// → 自动截断为 4 字 + console.warn + 挂 fail 回调，绝不静默
```

**② iOS 上 `new Date('2026-09-28T10:00:00')` 返回 Invalid Date**

JSC 对**无时区的 ISO 串**解析不一致，`getTime()` 得 `NaN`，于是
`hoursUntil` 返回 NaN → `!(NaN > 6)` 恒为真 → 所有课程都被误判为"不足 6 小时"，
再撞上上面那个超长文案，就彻底"没反应"了。

改为**拆数字构造**，并给 NaN 兜底：

```js
function toDate(dateStr, timeStr) {
  const dp = dateStr.split('-'), tp = (timeStr||'00:00').split(':')
  return new Date(+dp[0], +dp[1]-1, +dp[2], +tp[0], +tp[1], 0, 0)
}
```

> 教训：小程序里跨端日期一律用数字构造，不要用字符串解析。

### 学员自助签到 / 取消

入口在**学员端「我的课表」→ 待上课**，每张课卡底部：

```
┌────┬────────────────────────┐
│ 28 │ 声乐            [已约]  │
│ 9月│ 10:00–10:45             │
│    │ [ 签到 ]  [ 取消课程 ]  │
└────┴────────────────────────┘
```

| 操作 | 规则 |
|---|---|
| 操作 | 规则 |
|---|---|
| **签到**（老师与学员**同一套规则**） | 只能给「**当天 或 已开课**」的课签到；未来的课一律拒绝，过去的课允许补签 |
| **学员取消** | 距开课 **> 6 小时**才允许自行取消 |
| 学员取消被拦 | 弹窗说明「距开课不足 6 小时」+ 显示老师电话，并提供**一键复制** |
| **老师取消** | **不受时间限制** |

签到规则实现在 `lessons.canCheckIn()` 一处，老师端 `complete()` 与学员端
`completeByStudent()` 都调它，两端界面按钮也按同一个结果显隐 ——
不会出现「按钮能点、数据层却拒绝」的不一致。

### 取消后的两种结果（按是否已过**结束时间**）

`lessons.cancel()` 返回 `{ ok, released }`：

| 情形 | 结果 | 界面表现 | toast |
|---|---|---|---|
| **课还没上**（`timeEnd` 未到） | 释放为 `available`、清空学员 | 「还没有人约课」+ 待约标签，重新开放给他人约 | 已释放为待约 / 名额已释放 |
| **课已结束**（`timeEnd` 已过） | 标 `cancelled`、**保留学员名单** | 仍显示是谁上的 + 已取消标签 | 已取消 |

取消确认弹窗会**预先说明后果**，不让人猜：

```
课还没上 → 这节课还没上，取消后会释放为「待约」、清空学员，其他同学可以重新约。
课已结束 → 这节课已结束，取消后会保留学员名单并标记为「已取消」。
```

约课管理按钮按状态收敛，每行最多两个：

```
待约            →  [指定学员]  [删除]
已约            →  [签到]（仅当天/已开课） [取消课程]
已取消 / 已完成 →                       [删除]
```

6 小时规则在**数据层强制**（`lessons.cancelByStudent()` 自己会算并拒绝），
不是只挡按钮 —— 绕过界面直接调用同样会被拦下并返回 `reason`。
界面与数据层共用 `date.hoursUntil()` 一个实现，不会两处算出不同结果。

### 主键字段坑（已修）

课表记录主键是 `id`，但学员端 3 个页面模板里写的是 `item._id` / `wx:key="_id"`。
`item._id` 取到 `undefined` → `lessons.book(undefined)` → 查不到 →
提示「课程不存在」。**学员约课按钮一直是坏的**，直到这次才暴露出来。

教训：字段名在 store 与模板之间没有类型约束，只能靠一致性检查。
现在全站页面层已无 `_id` 残留。

### 学员身份链路（重要修复）

之前课表 `students` 存的是**名册 id**（`s1`），但学员端页面用 **openid**
（`mock_student_135…`）去匹配，而 `lessons.book()` 会拿这个 id 去
`students.snapshot()` 查，查不到就被 `.filter(Boolean)` 丢掉 ——
**学员自助约课会静默失败**：点了约课、toast 也弹了，课却还是「待约」。

现在登录时就绑定名册 id（`userInfo.sid`）：

| 情况 | 处理 |
|---|---|
| 名册已有该手机号 | 直接用名册 id（老师提前录的老学员） |
| 名册没有 | **自动入册**（备注「自助注册」），老师端立刻能看到 |
| 同名冲突等异常 | 退回 `p_<手机号>`，至少不串号 |

4 个学员页（首页 / 约课 / 课表 / 记录）统一按 `sid` 匹配。

#### 旧 session 自愈（重要）

`sid` 是**登录那一刻**写进 session 的。在修复之前就已登录的用户，
本地 session 里**永远不会有 sid**，回退成 openid 后约课依旧会静默失败。

所以 `app.getStudentId()` 会惰性修复：

```
有 sid → 直接用
没有   → 按手机号回查名册 → 拿到 id → 回写 session（下次直接命中）
名册也没有 → 自动入册（备注「自助注册」）
异常       → 退回 p_<手机号>，至少不串号
```

`app.myStudentKeys()` 返回 `[sid, openid, p_手机号]` 一组键，
匹配课表时任一命中即算"我的课"，兼容历史数据。

#### 约课不再假报成功

`lessons.book()` 现在返回 `{ ok, students, reason }`，并且**名册查不到时
保留 `{id, name}` 而不是丢弃**。调用方必须检查 `res.ok`：

```js
const res = lessons.book(id, [{ id: sid, name: me.name }])
res.ok ? toast('约课成功') : modal('约课失败', res.reason)
```

被拒的情况：课程不存在 / 已完成 / 已取消 / 学员身份无效。

### 学员课时与报名档案

为**小程序上线时录入老学员**而设计（这些数据系统里查不到，只能老师手填）：

| 字段 | 说明 |
|---|---|
| `totalLessons` | 共报几节课 |
| `doneBefore` | **上线前**已上几节 |
| `enrollStart` / `enrollEnd` | 报名起止日期（选填） |
| `note` | 备注（仍可填，只是不在列表展示） |

**「已上」是活的**：`已上 = doneBefore + 系统内 status=completed 的课`。
老师录入的是上线前的历史节数，之后在小程序里签到完成的课会自动累加上去，不用回头改数字。

列表小字只显两项，**不显「待上」和「备注」**（备注可能很长会把行撑乱）：

### 信息展示弹层（不用 showModal 塞多行）

`wx.showModal` 的 `content` **不保证支持 `\n` 换行**，多机型会把多行压成一整段。
凡是需要多行展示的地方都改成自定义底部弹层：

| 位置 | 内容 | 交互 |
|---|---|---|
| 我的 → 联系我们 | 电话 / 微信 / 地址 / 开放时间，**每条独立一行** | 点任意一行单独复制该项 |
| 我的 → 关于工作室 | 工作室介绍整段 | — |

地址这类长文本用 `word-break: break-all` + 右对齐，不会挤坏布局。

### 表单控件对齐（小程序原生坑）

两个坑，成因不同：

| 控件 | 症状 | 成因 | 解法 |
|---|---|---|---|
| `<input>` | 文字忽上忽下 | 文本垂直居中**不跟随上下 padding**。原 `.field-i` 写了 `padding: 32rpx` 四边 + `height: 112rpx`，内容区只剩 44rpx，小于字号行高 | 只留左右 padding：`padding: 0 32rpx; height: 112rpx; line-height: 108rpx` |
| `<textarea>` | 内边距时有时无 | 它是**原生层组件**，CSS `padding` 常被忽略或应用不一致 | padding 与边框移到外层 `.ta-box` 容器，textarea 自身 `padding: 0; height: 100%` |

`.field-i` 是全局类，此修复同时覆盖登录、排课、约课管理、学员、老师、课程类型、工作室信息共 7 个页面。

### 课表时间显示（修复）

`lessons` store 原先只存 `timeStart / timeEnd / minutes`，**没有 `timeSlot` 字段**，
而 5 个页面模板都在渲染 `item.timeSlot` → 时间全站不显示。

### 为什么第一次修没生效

第一次只给 `seed()` 和 `addMany()`（新写入）补了字段，但**修复前已存在本地缓存里的课**
仍然没有 `timeSlot`，而 `list()` 不会覆盖已有缓存 → 时间照旧空白。

正确做法是**在读取入口归一化**：

```js
function normalize(l) {                                   // 缺什么补什么
  if (!l.timeSlot) l.timeSlot = l.timeStart + '–' + l.timeEnd
  if (!l.minutes)  l.minutes  = 分钟差
  return l
}
function list() { return saved.map(normalize) }           // 所有读取都走这里
```

`all()` / `forDate()` 都经由 `list()`，所以渲染 `timeSlot` 的 5 个页面一次性修好，
并且**自愈** —— 下次 `save()` 会把补齐后的记录写回缓存。
接云开发后即使服务端数据缺字段，前端也不会再出现空白。

约课管理里时间改为卡片主信息：**加粗钴蓝** + 时长陶土橙徽标 + 日期右对齐。

```
声乐  [待约]
16:00–16:45  45分          今天
 ↑ 加粗主信息  ↑ 时长徽标    ↑ 次要
```

### 权限模型

老师登记表统一在 `utils/teachers.js`（登录判定与授权都以它为准），每条记录：

```js
{ id, name, phone, isSuperAdmin, perms: { editStudio: true|false } }
```

判定入口 `teachers.can(teacher, key)` 与 `app.can(key)`：
**超管天然拥有全部权限**，其他老师需被显式授予。

| 保护规则 | 原因 |
|---|---|
| 超管权限不可单独收回 | 超管本就拥有全部，收回无意义且会造成状态矛盾 |
| 最后一个超管不可降级 / 不可删除 | 否则会没人能再管理老师与权限 |
| **降级超管时同步收回全部权限** | 这些权限当初是「因为是超管」才有的，不收回会出现「已降级却仍保留全部权力」的越权残留 |
| 提升为超管时自动全开权限 | 与 `can()` 的超管短路保持一致 |

超管在「老师」页点开任意老师 → 弹层里有权限开关区，可勾选「工作室资料」，
也可直接把人提升为超级管理员（开关会联动权限）。

### 按钮文字换行修正

小程序 `<button>` 默认宽度自适应，长文案（如「+ 添加课程类型」）会被挤到换行。
把 `.btn-full`（满宽）与 `.btn-nowrap`（强制单行）提到全局 `app.wxss`，
所有表单主按钮统一加上，文字稳定一行显示。

> 本项目 14 个页面均为 `wxml / wxss / js / json` 四件套，新增页面时记得一并创建。
>
> 页面 json 里除了 `usingComponents`，还按各页顶部色带设了 `backgroundColorTop`，
> 避免下拉回弹时闪白（例如老师端顶部是钴蓝，就设 `#2B3FA8`）。

```

├── cloudfunctions/
│   ├── login/      # openid + 手机号解码 + 身份判定 + 写 members
│   ├── sync/       # 拉取 / 推送 / 学员约课（服务端权限校验）
```
