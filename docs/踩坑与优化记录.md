## 一、平台兼容性

### 1.1 `wx.showModal` 按钮文案最多 4 个字，超出**静默失败**

- **症状**：点「取消课程」「复制电话」完全没反应，弹窗不出现，**控制台一个错误都没有**。
- **成因**：`confirmText` / `cancelText` 超过 4 个汉字时接口直接失败，且默认不回调。
- **踩到的三处**：`'复制老师电话'`(6)、`'以学员身份进入'`(7)、`'换个手机号'`(5)。
- **解法**：全站统一走 `utils/dialog.js`，它自动截断到 4 字 + `console.warn` + 挂 `fail` 回调。

```js
const dialog = require('../../utils/dialog.js')
dialog.show({ title, content, confirmText: '复制老师电话' })   // 自动变 4 字并告警
```

> 教训：**任何"点了没反应"先怀疑弹窗文案长度**，别去查业务逻辑。

### 1.2 iOS 上 `new Date('2026-09-28T10:00:00')` 返回 Invalid Date

- **症状**：Android 正常，iOS 上"所有课都提示不足 6 小时不能取消"。
- **成因**：JSC 对**无时区的 ISO 串**解析不一致 → `getTime()` 得 `NaN` → `hoursUntil` 返回 NaN → `!(NaN > 6)` 恒为真。
- **解法**：拆数字构造 + NaN 兜底。

```js
function toDate(dateStr, timeStr) {
  const dp = dateStr.split('-'), tp = (timeStr || '00:00').split(':')
  return new Date(+dp[0], +dp[1] - 1, +dp[2], +tp[0], +tp[1], 0, 0)
}
```

> 教训：小程序里跨端日期**一律数字构造**，不要解析字符串。

### 1.3 `showModal.content` 不保证支持 `\n`

多机型会把多行压成一整段。凡要多行展示（联系信息、冲突清单、工作室介绍）一律改用**自定义底部弹层** `.mask + .sheet`，每条信息独立一行、可单独复制。

### 1.4 `<input>` 上下 padding 导致文字垂直漂移

- **症状**：同一批输入框，文字有的贴顶有的贴底。
- **成因**：文本垂直居中**不跟随上下 padding**。旧 `.field-i` 写 `padding: 32rpx`（四边）+ `height: 112rpx` → 内容区只剩 44rpx，比行高还小。
- **解法**：`padding: 0 32rpx; height: 112rpx; line-height: 108rpx`。`.field-i` 是全局类，一次修好 7 个页面。

### 1.5 `<textarea>` 的 padding 不生效

它是**原生层组件**，CSS `padding` 常被忽略。解法：padding 与边框放外层 `.ta-box` 容器，textarea 自身 `padding: 0; height: 100%`。

### 1.6 `<button>` 长文案被挤到换行

小程序 button 默认宽度自适应，「+ 添加课程类型」这类会折行。解法：`.btn-full`（满宽）+ `.btn-nowrap`（强制单行）提到全局 `app.wxss`，主按钮统一挂上。

### 1.7 部分安卓机型 `:active` 不触发

按钮按下没有反馈。解法：**CSS `:active` 与 `hover-class` 双保险**，并给 `hover-stay-time="90"`。

### 1.8 WXSS 不能引用本地图片路径

`background-image: url('/images/dog.png')` 不显示。解法：全部 **base64 PNG 内联**（约 51KB，10 彩色 + 7 水印），源文件留在 `assets/`、`images/` 便于再生成。

### 1.9 新版开发者工具强制要求每个页面有 `.json`

升级工具后 14 个页面全部报「缺少 json 文件，无法注册为页面」。解法：每页补齐 wxml / wxss / js / **json** 四件套（`tools/check_project.py` 会检查）。

## 二、数据一致性

### 2.1 主键是 `id`，不是 `_id`

- **症状**：学员点约课提示「课程不存在」——**这个按钮从上线第一天起就是坏的**。
- **成因**：课表记录主键是业务 `id`，但学员端 3 个页面模板写的是 `item._id` / `wx:key="_id"` → `undefined` 传进 `lessons.book()`。
- **教训**：字段名在 store 与模板之间没有类型约束，只能靠**一致性检查**兜住（现已全站无 `_id` 残留）。

### 2.2 模板渲染了 store 里不存在的字段

`lessons` 只存 `timeStart / timeEnd / minutes`，而 **5 个页面**都在渲染 `item.timeSlot` → 全站时间空白。

### 2.3 为什么第一次修没生效（重要）

第一次只给 `seed()` 和 `addMany()`（**新写入**）补字段，但修复前已在本地缓存里的课仍然没有 `timeSlot`，而 `list()` 不覆盖已有缓存 → 照旧空白。

正确做法是**在读取入口归一化**：

```js
function normalize(l) {                       // 缺什么补什么
  if (!l.timeSlot) l.timeSlot = l.timeStart + '–' + l.timeEnd
  if (!l.minutes)  l.minutes  = 分钟差
  return l
}
function list() { return saved.map(normalize) }   // 所有读取都走这里
```

`all()` / `forDate()` 都经由 `list()`，一次修好 5 个页面，并且**自愈**（下次 `save()` 把补齐结果写回缓存）。接云开发后即使服务端缺字段，前端也不会空白。

### 2.4 种子数据加字段：`SEED_VER` + `upgrade()`

`list()` 只在缓存为空时播种 → 后加字段永远到不了老设备。于是引入版本号：

```js
const SEED_VER = 2      // 给 SEED 加字段就 +1
```

两个易错点（都踩过）：

```js
// 坑 1：不能把 0 / '' 当"缺失"——那是老师有意填的合法值
if (!(k in out) || out[k] == null) out[k] = seed[k]     // ✓
// ✗ 旧写法把 cur === 0 当缺失 → 新学员 doneBefore=0 被种子的 8 覆盖

// 坑 2：upgrade 必须作用于"原始缓存"
const rows = normAll(upgrade(saved))                    // ✓
// ✗ normAll(upgrade(normAll(saved)))：内层 normalize 已把字段补成 0，
//    upgrade 再也分不清「老缓存没这字段」和「老师填了 0」，补齐失效
```

### 2.5 学员身份：openid 与名册 `sid` 不一致 → 约课**静默失败**

- **症状**：点了约课、toast 弹「成功」，回列表课还是「待约」。
- **成因**：课表 `students` 存名册 id（`s1`），学员端页面拿 openid（`mock_student_135…`）匹配；`lessons.book()` 用这个 id 去 `students.snapshot()` 查不到，被 `.filter(Boolean)` 静默丢掉。
- **解法**：登录时就绑定名册 id（`userInfo.sid`）。

| 情况 | 处理 |
|---|---|
| 名册已有该手机号 | 直接用名册 id（老师提前录的老学员） |
| 名册没有 | **自动入册**（备注「自助注册」），老师端立刻可见 |
| 同名冲突等异常 | 退回 `p_<手机号>`，至少不串号 |

### 2.6 旧 session 自愈

`sid` 是**登录那一刻**写进 session 的，修复前就已登录的用户本地永远没有 sid。所以 `app.getStudentId()` 惰性修复：有 sid 直接用 → 没有则按手机号回查名册并**回写 session** → 名册也没有就自动入册 → 异常退回 `p_<手机号>`。匹配课表时用 `app.myStudentKeys()` 返回 `[sid, openid, p_手机号]` 一组键，任一命中即算"我的课"。

### 2.7 写操作必须返回 `{ ok, reason }`

`lessons.book()` 现在返回 `{ ok, students, reason }`，且**名册查不到时保留 `{id, name}` 而不是丢弃**。调用方必须判断：

```js
const res = lessons.book(id, [{ id: sid, name: me.name }])
res.ok ? toast('约课成功') : modal('约课失败', res.reason)
```

> 教训：**只在真正成功时才提示成功**，否则界面与数据会长期不一致且极难排查。

### 2.8 课时口径：基线 + 增量；超支不能被 `Math.max(0, …)` 吞掉

- **已上是活的**：`已上 = doneBefore(上线前历史节数) + 系统内 status=completed`。老师交上来的表单填的是**总已上**，提交时换算成基线：

```js
doneBefore = max(0, 老师填的总已上 − 系统内已完成数)
```

否则会出现"列表显示 12，进表单改成 12，保存后变成 16"的数字跳变。

- **超支要如实显示**：旧代码把 `remain` 钳在 0，看起来"刚好上完"，其实已经超支。现在 `remain = total - used` 允许为负，`over / overBy` 单独给出：学员端档案卡变砖红「已超 N 节」、老师端学员列表加红色标记、签到后若导致任一学员超支**当场弹窗**列出是谁超几节。

- **模块拆分**：`students` 与 `lessons` 互相有依赖，汇总逻辑放任意一边都会循环引用 → 独立成 `utils/quota.js`。

## 三、交互与状态

### 3.1 登录身份要拆成两层状态

- **症状**：从登录页点返回首页，直接被弹进老师端。
- **成因**：点击入口时就写入了 `role`，而首页 `onShow` 检测到 role 就自动跳转。
- **解法**：

| 状态 | 含义 | 何时写入 |
|---|---|---|
| `pendingRole` | 只是"点了哪个入口"的意图 | 点击入口时 |
| `role` + `session` | 已确认的登录身份 | **登录成功后** `app.signIn()` |

配套：首页 `onShow` 只在 `isLoggedIn()` 为真时跳转；首页→登录用 `navigateTo`（返回键=真回上一页）；登录页去掉「切换身份」改为「回到首页」(`reLaunch` 清栈)；登录成功 `reLaunch` 进工作台；退出走 `app.signOut()`。

### 3.2 「点了确认但课没出现」

早期确认排课只弹了个 toast，数据其实写死的假列表。现在真正写入 store，返回后首页与约课管理都能看到；有冲突时弹窗逐条列出被拦时段与原因，**成功的照常排入**（部分成功）；日期卡显示该日已排节数。

### 3.3 卡片按钮溢出被裁切

「指定学员 + 签到 + 取消」三枚 `<button>` 需要 484rpx，内容区只有 466rpx。解法：左侧日期栏 140→**118rpx**、内容区内边距收窄（可用宽度升到 496rpx），按钮换成 `view` + `flex: 1 1 30%; min-width: 132rpx` 等宽自适应，再加 `flex-wrap: wrap` 兜底。

### 3.4 取消课程必须按「是否已过结束时间」分两种结果

`lessons.cancel()` 返回 `{ ok, released }`：

| 情形 | 结果 | 界面 |
|---|---|---|
| 课还没上（`timeEnd` 未到） | 释放为 `available`、清空学员 | 「还没有人约课」+ 待约，重新开放 |
| 课已结束（`timeEnd` 已过） | 标 `cancelled`、**保留学员名单** | 仍显示是谁上的 + 已取消 |

如果一律显示"已取消+没人约"，历史课在对账时就变成无名记录；如果一律保留占位，又会让别人约不到课。**确认弹窗预先说明会发生什么**，不让人猜。

### 3.5 界面与数据层必须共用同一套判定

签到（仅当天或已开课）、学员取消（距开课 > 6 小时）都实现在 `lessons.canCheckIn()` / `cancelByStudent()` 一处，老师端与学员端都调它，按钮显隐也按同一结果计算 —— 不会出现"按钮能点、数据层却拒绝"。规则在**数据层强制**，绕过界面直接调用同样被拒并返回 `reason`。

### 3.6 两个"想当然"的细节

- 固定课添加后**不再自动顺延**开始时间（它已占住整周，顺延没意义）。
- 每加一个时段要**自动清空**已选学员，否则会把上一节的学生误带进下一节。

## 四、视觉与工具链

| 坑 | 说明与解法 |
|---|---|
| **线条画不能用 SVG `stroke`** | 实测 ImageMagick 与小程序渲染器都会直接丢弃 `fill="none" stroke="…"` 图形，线条画全白。约克夏与卡通箭头改用 **Pillow 直绘**（Catmull-Rom 平滑 + 圆头圆角）后导出 PNG |
| **Hiragino 缺字形** | 缺 `› ✓ ✕ ⭐ ⑪⑫⑬`，渲染成方框叉。原型图脚本里这些符号一律**手绘**（`chevron()` / `xmark()` / `checkmark()` / 序号徽标） |
| **Pillow RGB 画布不接受 `rgba()`** | 传 `rgba(...)` 字符串直接 ValueError。用 `mix(hex, alpha, bg)` 先算成实色 |
| **原型图与代码不同源** | 手绘示意图会跟产品越差越远。`tools/render_mockups.py` 直接读 `images/*.png`、按 `app.wxss` 的真实间距渲染，1 rpx = 1 px，2x 超采样后缩 50%，并按内容底部自动裁切 |

## 五、怎么验证

| 层次 | 做法 |
|---|---|
| 静态 | `python3 tools/check_project.py`：页面四件套与 `app.json` 注册、WXML 标签配平、`bind*` 事件函数存在、`require` 路径有效、WXML 用到的类在 wxss 中存在、`showModal` 按钮文案 ≤ 4 字、`node --check` 全量 JS 语法。CI 每次 push 自动跑 |
